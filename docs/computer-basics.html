RAM, cores and load

A computer has two budgets that a job spends: memory (space, held while the job runs) and CPU cores (time, spent while it works). Run out of either and everything slows down.

1. Memory is a desk, cores are hands

RAMCores
What it isWorking memory, in GBParallel workers, counted in cores (this Mac has 18)
A job uses itHeld for the whole run; peak mattersSpent only while computing; shared by time slices
Too much meansThe Mac swaps to disk and freezesJobs slow down, the UI gets sluggish
Why the bouncer caresNever over-commit itDon't stack jobs that all want every core

4. How one job spends both

Why peaks, not averages. The bouncer records each job's peak RAM (sampled every 2 s) and peak cores (CPU time over 4 s windows). RAM must be reserved for the whole run, and the peak is what freezes a Mac. A job that is at 50 MB now but peaks at 5 GB still counts as 5 GB.

5. Terms

TermPlain meaning
Peak RSSThe most physical memory the job's processes held at once, added up. Shared memory can count twice.
Process groupA job and everything it starts (workers, browsers). The bouncer measures and cleans up the whole group.
SwapDisk space used as overflow memory. Used swap means the machine already ran short.
Free vs availableThe bouncer counts only free, purgeable and file-cache memory as room. Inactive app memory is not room.
Core budgetSum of the cores each running job is expected to use. A new job must fit in what is left.
Ramp-upA new job takes seconds to reach full use, so the next big job waits 2 s.
